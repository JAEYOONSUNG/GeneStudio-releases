#Getting started

Gene Studio is one application on three platforms and one file inside all of them. There is no project to create and nothing to import: you open a construct and it is open.

#Installing

PlatformWhat you getUpdates
macOSA signed, notarized .dmg. Drag it to Applications.One press, in place.
WindowsAn NSIS installer (-setup.exe), or a portable .exe.One press, in place.
LinuxAppImage — one file, run it. Or a .deb for apt.The AppImage updates itself; a .deb belongs to your package manager and says so.
Browser / phoneThe same page over https. On iOS: Share → Add to Home Screen.Reload.

The browser build is a viewer. Everything that reads a construct is there — the three drawings, the digest and its gel, the alignment, find, fold, the enzyme database and every export. What is off is everything that would change the construct, because a browser cannot save the change back to the file it came from, and a viewer that quietly loses an afternoon's edits is worse than one that never offered them.

#The licence

The app is free during the beta and is given to named people. A licence is a few lines of signed text, verified on your own machine — nothing is sent anywhere, so it works on a plane, and there is no server to be down.

  1. Open the app. The licence window shows your Machine ID — twelve hex characters that identify the computer to nobody but the licence.
  2. Press Ask for a licence. It fills in a message with your name, e-mail, lab and country, copies the whole thing to the clipboard, then tries your mail client. If nothing opens, paste it into any mail — the address is printed as text so it can be typed.
  3. Paste the block that comes back between the fenced lines, and press Unlock.
What comes back
===== COPY EVERYTHING BETWEEN THESE LINES ===== ----- GENE STUDIO LICENCE ----- holder: Your Name <you@lab.ac.kr> machine: A1B2-C3D4-E5F6 issued: 2026-08-26 expires: 2026-09-25 … ===== END OF LICENCE =====
Paste it whole, fences and all — the window strips them. It also puts the line breaks back if your mail client ran them together, drops > quote markers, and says which part is missing as you paste.

A licence is bound to one computer, so the same file will not run elsewhere. It ends by itself; you are told in the last week, once per launch, with the date and the address to write to. Changing machines means asking again with the new Machine ID.

#The first launch

A demonstration construct opens so there is something to press. It is called pDEMO-T7 — 2,950 bp, circular, 13 features — and the regulatory elements in it are real sequences while the stretches marked filler are generated. It is not from any published plasmid, so nothing in it should be cited.

After that the app opens whatever you last had open. The ⌂ button in the toolbar, or ⇧⌘H, goes back to the library.

#Your files

Nothing is uploaded anywhere. The library is a record of where your files are, not a copy of them, and a construct you open is read off the disk each time so an edit made in Finder is visible at once.

#What it opens

Anything else that looks like a sequence — a bare stretch of bases pasted from an e-mail, with line numbers and spaces in it — is read as one.

Four ways in

  • Drag and drop onto the window. Several constructs open as several tabs (up to eight; the rest go to the library and it says so). Several traces all attach to the construct in front of you.
  • Open a folder and every sequence and trace under it is listed, and stays listed the next time. Scanning attaches and opens nothing — saying where files are is not asking to read them.
  • Double-click in the Finder. On Linux the file types are registered by their bytes as well as their names, so a GenBank record saved as .txt still opens here.
  • Paste — ⌘V with nothing selected opens a box. Paste bases or a whole record; it becomes its own tab.

A cloud file that is not on disk is fetched when you open it. Dropbox leaves a 0-byte placeholder for a file kept online-only — that is not a corrupt file, and the app says so and pulls it down. It only does this for a file you asked for: a folder scan never downloads anything.

#The library

The home screen groups the library by folder, newest-used first, with a Recent row of the last four across the top. Right-click a tile for Show in Finder, Rename… (the label here only — the file on disk is untouched) and Remove from library.

The search box above it takes four forms, and they combine:

Searching the library
pG1t + RS15380 both terms must match pG1t -Jet matches pG1t, but not if "Jet" is in it "a plain vector" the phrase, spaces and all /v[23]\.gbk$/i a regular expression
A bare space is not a separator — plain vector still finds "a plain vector.dna". Only an exclusion is split off, and only at a word boundary, so the hyphen inside pG1t-Pgap is not one.

Korean filenames work: macOS stores them decomposed and the box folds both sides to one form before they meet, so typing 박정수 finds Primer Box 박정수.

#Assemblies and multi-record files

A draft genome is one file and many molecules. Open a .gbff of 186 contigs and they are listed down the side: press one and the map, the sequence, the features and the record drawer are all that contig's. A contig you edited keeps its edits when you switch away and back, and is marked.

Saving writes the whole file, not the contig. The record on screen is written in place and every other record is carried through byte for byte, so a three-record file stays three records. Where the file has moved, or no longer holds that record, the save is refused with the reason rather than writing one molecule over an assembly.

#The three drawings

One molecule, drawn three ways, and each answers a different question. They do not share their layer switches: what has to go to make a ring legible is not what has to go for a row.

#The map — ⌘1

The whole construct at a glance. The backbone is two concentric strands: top-strand features sit outside the pair and bottom-strand ones inside, so which strand a gene is on needs no arrowhead to work out. A cut is a tick through the backbone rather than a mark beside it, and a name that will not fit on its own arc goes out to the margin on a leader.

  • Drag the ring and it measures — the arc, and how many bases it is.
  • Click two cut sites and the distance between them is drawn. Click more and every span between consecutive picks is drawn at once. Click bare ring to clear.
  • Hover an enzyme name and every cut that enzyme makes lights up.
  • Double-click a feature — its arc or its name — to open it. Double-click a primer anywhere it is drawn to edit it.
  • Right-click anything for what can be done to it.

A linear molecule is drawn on the same ring with a 20° gap at the top and both ends capped, rather than as a second copy of the linear view.

On a genome the ring draws a spread of landmarks rather than every locus, and says so in its own centre: 96 of 8,338 features · zoom in for more. The number it can draw grows with the square of the zoom. Cut sites start off above 400 kb, because a chromosome is cut somewhere by nearly everything and the layer is a red band rather than a reading.

#The linear view — ⌘2

The same molecule unrolled, on one line by default. Zoom is how much of the molecule is on screen — 1 is all of it, and past that the window is held by its centre so zooming closes on what you were looking at. The caption says which stretch is drawn, so a zoomed figure is a figure and not a picture.

Taking a figure of one gene out of a chromosome
4.67 Mb genome, Linear view zoom 1 all of it, 24 rows, 4,647 coordinate labels zoom 100 46,715 bases, 68 labels zoom 600 2,998,591–3,006,376 on one row — rpoB and rpoC as two arrows with a ruler over them
Then Export → Map / Linear (.pdf): vector, text as text, editable in Illustrator.

#The sequence — ⌘3

The bases, and this is the view that can be edited. A line reads the way a map does, top to bottom: the enzyme names and their ticks, the primers that read 5′→3′, the sequence with its complement, each translation drawn directly under its own residues, and then the primers that read 3′→5′ hanging under the strand they run backwards along.

  • Each stretch is drawn as one card, so a feature bar inside it belongs to that line and not to the one above.
  • A feature above the top strand is on the top strand; one below the bottom strand is on the bottom strand. There is nothing to work out.
  • A cut is a stepped ㄴㄱ through both strands, so which strand breaks where — and which way the overhang points — reads off the bases.
  • A primer is drawn as what it is: the annealed bases on the line, the 5′ overhang and any designed mismatch stepped down out of the shaft, the 3′ end an arrowhead.
  • Residues are one letter or three (A / Ala) — the picker is in the tool strip, and a mutation quoted Ala41Val in a paper needs no converting in your head.

The strip along the bottom of the sequence and linear views is the navigator: the whole molecule as a bar with every feature on it, the picked enzymes as red ticks, and the part you are looking at as a lit box. Click to jump, drag to scrub, wheel to roll, ⌘-wheel to change how much of the molecule it shows.

#DNA, IUPAC and patterns

What the DNA box takes
GAATTC plain bases, both strands GGNRCC IUPAC — N is any base, R is A or G GG.{3,8}CC a pattern: GG, three to eight of anything, CC (GAATTC|GGATCC) either site [AT]{6,} six or more A/T in a row /gaattc/i a pattern that happens to be all letters
Anything carrying a metacharacter is compiled as a pattern; a query that will not compile falls back to a literal search rather than throwing the bar away. Hits are marked on all three drawings, faint for the ones you could step to and solid for the one you are on — and clicking a mark walks the search to it.

A hit that straddles the origin is kept as a wrapping selection, which is what the rest of the app already means by end < start. The same stretch found on the other strand is one hit, not two.

#The other four modes

Protein is searched only in coding regions — a feature carrying a /translation, a CDS, or any other feature that reads as an open frame. A six-frame scan would answer with peptides from frames nothing is read in, which are not proteins this construct makes. A recorded /translation wins over translating the bases, because it is what the record asked to be believed. X is any residue, * a stop, and a motif works:

A peptide motif
D..F or DXXF or D.{2,6}F
All three answer residues 2–5 of MDQAFKL… — and the hit's label names the gene and the residues (LacZ alpha · residue 5–10). On a construct with nothing translated the bar reads nothing translated, which is a different answer from "no hits".

Anything but the sequence reads name, type, note, product, locus tag, EC number, inference and any qualifier at all — including a qualifier's key, so "which of these has an EC number" is a search. It names the field that matched. The bases and the recorded translation are deliberately left out; that is what the other two modes are for.

Go to takes 1200, 1,200, 1200..1400, 1200-1400. A range that reads backwards crosses the origin — 7713..4362 selects the way round through base 1 — and on a linear molecule that is refused with the reason. Anything that is not a number is handed to the DNA search.

The last five queries of each mode are one arrow away (↑ / ↓), kept per mode and remembered between launches, and what you had half-typed comes back when you walk off the end of the list.

#When nothing matches

The bar runs the exact search alone and, finding nothing, says no exact match and offers Find similar beside the count. Widening is a different question from the one you asked — where is this has the answer "nowhere"; what nearly matches it is a second search — so it is offered rather than run, and asked again for every query.

A 500 nt fragment that has drifted
Paste it into ⌘F → no exact match [ Find similar ]
On a 1.88 Mb genome, a 500 nt query with 6% of its bases changed: found in 3 ms at 95.4% identity. A 20,000 nt query: 29 ms. The molecule is indexed once and after that a query costs its own length. Gaps are not answered — this is "where does this nearly bind", which is an ungapped question.

A sequence pasted wrapped — off a paper, with coordinates down the side — is joined into one query rather than searched line by line.

#Selecting and editing

A selection is one range, and every act below works on it. What is held — a feature, a primer — is a different thing, and the toolbar says which before you press.

Making a selection

  • Drag across the bases, the ring or the linear bar. The hover card follows with the three figures a drag is made for — how long, what it melts at, how GC-rich — up to 70 bp, past which those figures stop describing a primer.
  • Click a feature and its span is selected.
  • Either side by… in the right-click menu is the one that saves the most time: with a caret it selects N bases either side of it, and with a stretch already selected it grows that stretch by N at both ends. 50 to 5,000 in round steps, and the last one used leads the menu.
A gene and its flanks, in two clicks
Click the gene (300 bp) → right-click → Either side by 500
1,300 bp selected. Near the origin on a circle it wraps rather than stopping; on a linear molecule it stops at each end.

Delete acts on what is held, not always on the DNA. With a feature held it removes the annotation and leaves every base; with a primer held it removes the oligo and leaves the sequence; with a freezer tube held it does nothing and says why. Only with nothing held and a stretch selected does it delete bases — and the toolbar button says which of the three it will do before you press it.

Colour on the DNA

A highlight is a mark on the molecule, not a feature — it never appears in the feature table and is never written as an annotation. Select, right-click, pick a colour, and choose both / top / bottom: a mark can mean something about one strand. It is drawn on all three views, saved with the construct, and carried through GenBank and .dna in a form other readers pass over without complaining.

⌘Z undoes; every version is in History, laid out around the saves, with Open a copy and Revert to here as two different acts.

#Features

Double-click a feature anywhere it is drawn. The window's title is its name — type in it — and Type sits beside it, with the figures a feature is judged by in a row underneath.

  • Bases or residues. A coding feature reads two ways, and the switch is beside the label: the peptide is translated from the bases in the box, honouring /codon_start, so the two views cannot disagree about which bases they are of. The whole feature is in the box, in blocks of ten with the coordinates of each line either side of it.
  • Segments. A join(61..180,241..360) feature is one feature in two pieces, and the dialog reads and edits them: the first segment is in Start and End, the rest are rows under them. Two segments that overlap are legal — that is how GenBank records a programmed ribosomal frameshift.
  • Qualifiers keep the record's own order. They are dragged to reorder (or moved with the arrows from the grip), and Sort by name is a button rather than something the dialog does behind your back.
  • Ω beside the name opens a palette of the characters a lab actually uses — Δ, σ, ⁵⁴, ×, ′. Δ is the Greek capital letter, which is what a deletion is written with.

Splitting a feature

A gene interrupted by an insertion is still one gene. So what a split takes is the stretch to leave out: select the insertion inside the feature, right-click, and the feature closes over it. Join … back into one is the way back.

The Features tab — ⌘4

One picker, three depths:

DepthColumns
RecordThe ordinary feature table.
Full tableEvery field, and a column per qualifier in the record — a qualifier that appears once, on one feature of four thousand, still gets a column.
Full + computedAnd the columns that are in no GenBank: %GC, residues, kDa, pI, GRAVY, and the ribosome binding site with its spacer and score.

Past twenty columns the identity is pinned — name, and locus tag where the record has one — so scrolling 6,000 px right still says which gene a row is about. Columns · 5 hides whole blocks at once. The filter marks the match inside the cell, because filtering alone leaves you hunting a forty-column row for why it matched. All four arrow keys move a cell, not a row.

Export this table (.xlsx) writes what is on screen — the depth, the filter, the sort, the column order, the blocks that are on — built from the rows rather than scraped from the table, so it is not capped at the thousand rows drawn. A second sheet says which table it was.

On a draft genome, Every contig builds one table over the whole assembly with the contig as a column, and a picker narrows it to one. It is built by asking each contig the same question the open one is asked, so the computed columns cannot drift.

Labelling the drawings

A GenBank record carries several names for one feature. Label the maps by — in the map's layer panel, both tool strips and the Features pane — switches every drawing between /gene, /locus_tag, /product and /label. A record carrying locus tags opens labelled by them, because that is what every table and every BLAST hit uses.

Choose features… in the map's layer panel is the whole list at once with a preview beside it that follows every tick, plus All, None, Invert, Only these and a chip per type. A construct back from sequencing arrives carrying dozens of one-base variant features named C::G; one press hides them all.

#Primers

Three sources, three switches, and none speaks for the others: the construct's own primers, the freezer tubes, and the built-in universal set.

Making and editing one

Select a stretch, right-click, and take it forward or reverse-complemented — a reverse primer is the other strand, so it is offered as its own item. Double-click any primer, anywhere it is drawn, to edit it.

The dialog shows where it lands: a window of the construct drawn the way the Sequence panel draws it — the ruler, the features it sits under, both strands, the translation, and the oligo itself as the stepped arrow. It follows the box as you type, and a primer that binds more than once gets a chip per site. Four tiles carry what a primer is judged by, with the Tm on a fixed blue-to-red scale so 58 °C means the same thing here as in the read-out bar.

A primer that binds nowhere
It says so once, where the drawing would be, and why: the search holds the 3′ end exact — that is the end a polymerase extends from — allows a couple of mismatches 5′ of it, and prints the bases it looked for. A primer designed against another construct binds nowhere here however much of its 5′ half matches.

The freezer

Point Settings at your primer workbook — folder and a name pattern, both globs — and every tube in it is read at launch and cached until the file changes. The lab's own .xlsx is read in the browser: one sheet per box, a sequence column, a name column and a location column, found by name rather than by position, because the sheet is kept by people.

Matching is built on two facts about real primers:

  • A 5′ overhang matches nothing. Restriction sites, Gibson arms and Golden Gate ends are added at the 5′ end, so the 3′ end is what is searched for and the overhang is measured rather than required.
  • Mismatches inside the annealing are the point of a mutagenic primer. The allowance (Settings, default 2) is 5′ of the seed. Stopping at the first mismatch is what used to leave a perfectly good tube looking as though it bound nowhere.
On the demo construct, with the real workbook attached
5,436 tubes scanned in 8 ms — 31 bind, where an exact search finds 4. 26 of them have overhangs and 15 carry mismatches.

A tube is attached, not owned: it never reaches a saved file, which is checked on every way out. To keep one, tick it in the stock table and press Keep N with this construct, or right-click the arrow and Keep … with this construct. Where it sits in the freezer travels with it in the note, because the shelf position is the one part of a tube that does not survive being copied.

One oligo can be two arrows. A primer is drawn once per binding site, so deleting one that anneals twice takes two arrows and two names off the drawing — which is said with the name, before the press and after it.

Sequencing a gene

Right-click a gene → Sequence …, or the planner at the foot of the Primers view. It picks a tiling from the construct's own primers and every freezer tube that binds — the freezer is searched even when it is not attached, because a tube you already own is the one to reach for.

What a read is assumed to be
Mixed for the first 25 bases, good for about 700 after that, measured from the primer's 3′ end — so a forward primer reads downstream and a reverse one upstream. Among primers that reach nearly as far, the one nearest 55 °C wins. Gaps no primer reaches are reported, since that is where a new primer has to be designed.

#Enzymes and the digest

1,113 enzymes, parsed from REBASE and reconciled against each company's own catalogue. Every enzyme NEB sells is in it.

#Enzyme sets

The picker is on the Digest sidebar and on all three drawings — the map is where anyone notices there are too many cuts. The order is the same everywhere: what you pinned, then All, then one set per company, then the sets you saved.

  • A supplier is a set, with the count in the name — Vivantis (240), NEB (239), SibEnzyme (203), Thermo Fisher (183), Enzynomics (122), Takara (97) and twenty more. Half of them were read off the company's own catalogue rather than off REBASE, because REBASE is a mirror of what each company last sent it.
  • Your lab's set — type or paste names into Settings, or tick them in Choose enzymes…. What is recognised is said as you type (38 enzymes · not known: FooI), because a typo in the middle of forty pasted names is what cannot be found by reading them back.
  • From SnapGene reads your existing custom sets out of SnapGene's own folder. It is read-only; nothing is ever written there.

Show filters by cut count, and its default follows the pool: a curated set shows everything in it, while All or a big record shows the single cutters. An enzyme the filter dropped is named, not silently missing — searching for it answers directly: BglI (3×) cuts here, and Show is hiding it because it cuts more than once.

Enzymes that cut identically are one line, because listing MboI, DpnII, Bsp143I, BssMI, BstMBI and Kzo9I separately says there is a choice where there is none. The line opens, and it carries a warning mark when the members really disagree about methylation — which is the choice that is real.

#The gel — ⇧⌘G

  1. Type enzyme names into the four boxes. The list completes them — what cuts this construct, fewest cuts first — and ⇥ takes the one left. The gel redraws as the letters land.
  2. Click a well to load into it. Either order works: pick the well then the enzymes, or the enzymes then the well. An empty well you skipped stays empty.
  3. Suggest digests scores every combination for bands the agarose can actually resolve and loads the best few as lanes.

Beside the gel, the molecule itself is drawn divided at each cut and coloured by fragment, with its genes above it — because the question a digest is planned around is not how big are the pieces but which piece is my gene in. The legend names what each piece carries, and a feature a cut runs through is named as destroyed, in the cut colour.

Quoting a digest
Right-click the fragment table
5655+2723+2249+2005+1340 — largest first, the order you read a lane top-down. Also as one size a line for a spreadsheet, or the whole table as TSV. No thousands separators: this gets pasted into a calculation.

#Methylation

Two hosts, because they answer different questions: what the DNA in hand carries is a property of the strain it was grown in, and what it will meet is a property of the organism it is going into. Pick both and the table reads them — one line per methylase, the site, which base is marked, how many sites are in this construct, which enzymes of the current set that mark stops, and how many of the target's sites the DNA would arrive at unmarked.

Behind the verdict sit 2,672 published experiments from REBASE over 435 enzymes, drawn in REBASE's own colours — green cuts, orange impaired, red not cut — with every reference a link. Where REBASE has measured nothing for a pair, it says that, which is not the same as "cuts".

A blocked cut is called out under the gel, not only in the table below it: the enzymes, the site counts, and a dam−/dcm− host to grow the plasmid in.

Prices. Paste your own quote once (Prices…) and every enzyme row carries a per-unit figure and the cost of one 10 U digest. Built-in catalogue offers carry their vendor, region and the date they were read — a price belongs to an offer, and the same EcoRI is a different number in Seoul and in Boston.

#Cloning and design

Every panel here recomputes on each change and draws the construct that comes out, because a design you have to press a button to see is a design nobody iterates on.

A region of one construct into another — Clone, ⌘8

Two parents, and a region picked on each by pointing at it: each parent's whole molecule is drawn with its features on it, so clicking a feature makes it the region and dragging makes the region what you dragged over. The from/to boxes stay the truth and stay typeable.

The route is chosen by the length of the insert and both are named: two primers up to 60 nt, with the insert riding on the tails; four past that — two amplify the insert with the vector's own flanks as tails, two amplify the vector outwards. That is how NEBuilder designs one, and it is the difference between a design you can order and a 600-mer nobody sells.

What comes out
A new tab, not the file the vector came from: 6,428 − 76 + 1,158 = 7,510 bp, carrying the vector's registered primers, the four designed ones, and the donor's own features moved with its bases. A vector feature lying entirely inside the replaced region is dropped — the stuffer this design exists to remove.

Golden Gate — Assembly, ⌘9

Every Type IIS enzyme in the table is offered, not nine written out by hand; the conventional ones lead and the rest are marked needs a vector, because a published overhang convention exists only for vectors people publish. Cut offsets are derived from the enzyme table.

Guides and deletion arms — ⌘6

A port of the author's own R package, with the nuclease table, filter thresholds, composite weights and cut patterns copied rather than reinvented. Three products: gRNA only, deletion arms only, and gRNA + arms.

  • Which side of the spacer the PAM sits on is a property of the nuclease — SpCas9 · NGG · 3′ — and can be overridden for an engineered protein.
  • Off-target counts come from the open construct, not from Bowtie against a genome index, and the screen says so. Point it at another open document to count against a genome.
  • The editing vector is a real file you add by path, and starring it writes a complete snapshot — DNA, features, primers, sites — to its own store, so moving or changing the source cannot change your saved vector.
  • Both the gRNA site and the arm site are picked on the template's actual sequence, drawn with the same ruler, feature arrows and translations the Sequence view uses.

After design the comparison is vertical — Original template → exact replacement → Transformed vector — so each version gets the full width for its map and coordinates.

Silent mutations

Right-click a selection inside a coding sequence: the restriction sites in the current set that a synonymous change could create or remove there. Only bases inside the recognition window are touched, both orientations are tried, and each row shows the change as point mutations (c123t). Apply leaves the translation identical while the site appears or goes.

DNA or transcript is a choice, not a detail. The folding engine picks its parameters from the letters, and the same 51-mer folds to −10.6 kcal/mol with 10 pairs as DNA and −21.4 with 15 pairs as a transcript — a different energy and a different structure. The panel asks, and re-folds when the answer changes.

The genetic code

All 18 NCBI tables, written as what each differs from the standard code rather than as sixty-four letters apiece — which is how they are described in the literature and the only form a person can check by eye. The panel is the layout everybody has seen since 1966, with two things a printed table usually leaves out: the start codons are marked, and the reassignments are named in the header.

Why the table matters
Table 11 has the same sixty-four assignments as table 1 and differs only in what may begin a peptide — which is the whole reason a bacterial gene is annotated with it. Its starts are seven codons, including ATT and ATC; the standard code's are ATG, CTG and TTG. The feature panel names the table it judged by.

Keeping what you found

A row becomes a real feature — terminator, or repeat_region with /rpt_type and /rpt_unit_seq — with /inference saying what found it, which is what stops a prediction being read later as somebody's curation. Twenty terminators are added as one history entry, and a feature identical to one already there is not added again.

#Sanger reads — ⌘0

An .ab1 is a read of the open construct, not a construct of its own. Drop one — or twelve — and they attach and take you here.

  1. Point at your traces folder (type or paste the path, or Choose…). Every .ab1 under it is listed, grouped by folder or by day, newest first. Scanning attaches nothing.
  2. Tick what you want — a click ticks, a drag draws a band over several, the folder icon takes a whole run — and press Attach N.
  3. Read the pileup: the construct's own sequence as the axis, with the feature and primer tracks over it, the consensus, and each read with its chromatogram drawn in the same columns directly beneath its letters.

What the automatic check says

Every read gets one of six verdicts, and the Auto check menu is the filter: tick the verdicts you want to see. Detach shown · N then takes that whole group off in one act.

A base's own Phred is not enough to call a difference real. The end of a read decays into a stretch where a dozen calls disagree and several still score Q30. So a difference is judged on its neighbourhood's quality and on whether the read otherwise agrees around it. On the read this was built against, 46 differences became 2 worth looking at and 44 in the tail.

Inspect

One row: on the left a card carrying the position, the verdict, the gene, and the codon in the gene's own reading direction with the read's bases under it and the residue before and after — Arg4 → Lys4 · missense. On the right the peaks in the same columns, with the base ruled through every row. The Previous and Next arrow buttons step between the events worth looking at, substitutions and indels.

A read with an indel is aligned with a gap, not read as a wall of mismatches, and the seeds are chained — so a clone carrying a 116 bp tandem duplication comes back as 9 mismatches and one insertion at 99.2% identity rather than 111 mismatches at 83%. Where a read runs into another part of the construct entirely, that is said on screen (⇢ 3,675) rather than letters simply stopping.

Frameshift or not is worked out by translating the edit, so two indels that cancel are reported as cancelling: the frame returns: 2 indels cancel (net 0 nt), residues 47–61 differ. No arithmetic on len % 3 can tell you that.

BLAST a read

The moment a clone comes back as something else, the question changes: what is this. BLAST on the read's row searches the .ab1's own base calls — the trimmed span by default, because the mixed ends are what make a search answer noise. A submitted job is written down and survives quitting; the panel lists what is still owed and Pick it up fetches a finished one.

BLAST, InterProScan and eggNOG-mapper are the only things here that leave your machine, they run at somebody else's server, and each one has to be ticked before it is sent.

Two e-mails, not one. eggNOG-mapper's server does not start the job when you submit the form — it mails a link that has to be clicked to confirm it. That is the step people skip, and then wait a day for a result that was never started. Both are named, in order, and what you sent is written down.

The join is locus_tag first and protein_id only when every locus tag failed — the package's own rule, and not the obvious one: a partial failure is not a reason to switch keys, because two keys matching different subsets of one file is a merge nobody can check.

What a merge wrote can be taken back off. These columns are somebody else's answer and both services improve between releases, so each panel carries the same line — eggNOG-mapper has already answered for 59 genes here · 15 columns · Remove them — and it is one history entry to undo. The record's own /product, /note and /gene are never touched.

How long an InterProScan really takes
A job costs about the same whatever is in it — EBI's queue is the cost and the protein count is not. 1 protein 140 s; 25 in one job 83 s; 120 proteins in 5 jobs 215 s. So the panel estimates in rounds, not in proteins. A run can be stopped and what came back is kept.

A gene whose protein carries an internal stop is left out and counted rather than sent — both services refuse a *, and on a real genome that is 20 genes of 800 spoiling a run.

#Saving, exporting, figures

Two jobs and one writer cannot do both: what a save keeps is everything the app knows, and what you publish is a different object.

Saving

⌘S writes back over the file the construct came from, through a temporary file and a rename — so a save interrupted half way leaves the original, not a truncated file.

Save As makes a copy; it does not move the tab you are in. The copy opens as its own tab and becomes active; the original is left exactly as it was, at its own path, with its own unsaved edits if it had any.

Export

Export in the toolbar opens a dialog rather than downloading at once: the nine formats as rows that say what each is for, the file name as an editable field, and a preview of the real thing — a sequence format shows the file's own first forty lines with its line and byte count, a drawing shows the actual SVG with the export palette applied, and a .dna says what it is rather than showing bytes.

Figures

The drawing choices are in the export dialog, shown only for a format they describe, and each repaints the preview as it is changed: whether features sit in lanes beside the backbone or on it with a thin line between (the published plasmid figure), the palette, the background, the typeface, the label size, the padding, and whether the text stays text.

Show this on the map as well puts the export palette on the drawing that is on screen, so a figure is judged before it is a file rather than after.

A figure's typeface is part of the figure. Six stacks are offered rather than six names, because a font that is not on the reader's machine falls through to the next. Once a face is chosen it is chosen for all of the drawing — a figure set in Times with Menlo numbers is two typefaces in one picture.

#When something looks wrong

Most of these have been reported at least once, and every one of them has an answer on screen if you know where it is.

“An enzyme I know cuts this is missing”

Show is hiding it. The default is unique cutters only under a catalogue-sized pool, so an enzyme that cuts three times is dropped. The list names what the filter took out and carries one press back — and searching the enzyme box for the name answers directly.

“My primers are not showing”

Three sources, three switches. Primers in the layer panel is the construct's own; the freezer and the universal set have their own toggles. The freezer is off by default, because a construct should open showing its own oligos and not the lab's five thousand tubes.

“It deleted two primers at once”

It deleted one oligo that is drawn at two binding sites. The message says so with the name, before the press and after it.

“The file will not open — unrecognised format”

Read the sentence. A 0-byte file says it has no contents and that downloading it may be what is needed — on Dropbox that is an online-only placeholder, not a corrupt file. A file that really is unreadable says unrecognised.

“Opening a big file is slow”

Over 400 kb, or where the scan would cost more than a quarter of a second, the restriction scan is deferred past the first paint and the Scan button owns it. That is the difference between "slow to open" and "opens, then fills in". A 4.2 Mb genome with 8,338 features opens in about 1.2 s.

“The sequence view keeps jumping”

It should not, and every path that could was closed. If it still does, it is worth reporting with what you were doing — the Sanger panel's own scroll and the folded sequence's window are both restored across a render deliberately.

“Check again does nothing” / a pipeline is not found

Settings → External Pipelines is the authority, and it names each part separately — the binary, the daemon, the wrapper, the data — rather than answering "not configured", which covers three different problems and helps with none. A Prodigal installed in a conda env no shell has activated is found.

Reporting something

There is a bug report in the app that fills in the version, the platform and what was open. Or write to genestudio.help@gmail.com — and a critical bug is worth a month on your licence, which is said in the message where you will read it.
